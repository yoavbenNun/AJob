# AJob Instructions

Read `BEST_PRACTICES.md` completely before making changes in this repository.
Update it whenever work reveals a reusable project-specific lesson, failure mode,
or fragile external-site assumption.

Follow the global Codex working rules. In particular:

- Ask material questions with a recommendation before major implementation.
- Make minor, reversible decisions independently when a clear low-risk default
  exists.
- Use relevant specialist sub-agents for parallel work and an independent reviewer
  after major coding.
- Preserve user changes and inspect Git state before editing.
- Handle routine Git staging, commits, branches, pulls, and normal pushes
  automatically for this solo-developer project. Ask before destructive or
  history-rewriting Git actions.
- Keep scraping, filtering, storage, matching, and resume processing as separate,
  testable layers.
- Never submit job applications or rewrite a resume without explicit human approval.
- End every session with a handoff covering completed work and remaining work.
- Prefer simple, surgical changes with explicit success criteria. Avoid unrelated
  cleanup and stop when the requested behavior is verified.
- Keep context lean with focused searches, bounded output, progressive disclosure,
  and enough headroom for testing and unexpected failures.
- Caveman is opt-in concise mode only. It must not hide safety information,
  approvals, review findings, verification results, or session handoffs.
